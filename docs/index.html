Stop sensitive data before it reaches AI tools

A browser extension detects cards, Emirates ID, IBANs, emails, phones, API keys and passwords locally, then blocks or redacts them before they are pasted into ChatGPT, webmail or any web form. Only metadata leaves the browser.

What it catches

Detection runs inside the page. The matched value never crosses the extension boundary, so the raw text cannot be logged or leaked by the backend.

Credit cardsEmirates IDIBANEmailsPhone numbersAPI keysPasswordsCustom keywords

Block, warn or redact

Policy-driven actions per data type: hard BLOCK on send, WARN with Send anyway or Redact and send, and silent REDACT on paste.

Metadata-only reporting

REPORT_EVENT carries type, action, hostname and count. There is no text or content field in the event schema.

Team controls

Invites with 256-bit single-use tokens, seat limits, per-company policies, hashed-IP rate limits and Stripe billing.

How it is built

Four packages in one pnpm workspace. The web app is a Next.js dashboard, so the full product runs on a server; this page is the static project showcase.

shared/

Pure TypeScript detection library with unit tests. No browser or server dependency.

extension/

Manifest V3 Chrome extension built with Vite and React. Local detection, no raw text sent out.

web/

Next.js admin dashboard: auth, teams, invites, Stripe billing, PDF reports and the public Risk Scanner.

supabase/

PostgreSQL schema with row-level security on every table and service-role-only rate limit and Stripe ledgers.

Verified, not claimed

Executed against a local Supabase stack and a production Next build on 2026-10-14.
